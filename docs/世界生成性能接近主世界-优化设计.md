# 世界生成性能接近主世界：优化设计

状态：A/B 已实施，C 尚未实施；后续应用户要求运行了性能基准。实现与正确性验证见 `docs/世界生成性能A-B优化-实现与验证.md`，性能结果见 `docs/世界生成性能A-B优化-实测报告.md`。本文的数值目标是设计目标，实际结果以实测报告为准。

## 设计时目标与后来校正的基线

设计时使用的 Forge 旧对照为：主世界约 1,684 ms，第四层约 6,841 ms，比值 **4.06 倍**。后续检查该旧存档的 `level.dat`，确认它的主世界是**超平坦**，并非正常主世界。因此这个数值只能作为历史超平坦对照，不能再用来描述相对正常主世界的差距。正常主世界的新存档结果见实测报告。

原定目标是同条件下不高于**正常主世界**的 1.5 倍，进阶目标为 1.3 倍。设计时从旧超平坦 4.06 倍推算出的“还需降 63%”现已失去目标依据，不作为完成判定。本轮正常主世界三次对照测得第四层约为 0.50–0.53 倍；仍只代表固定区域和运行环境。

上一轮第四层自身的 6,241.94→5,315.45 ms 使用的是另一套 FULL 区块基准，不可与上述 1,684 ms 拼成跨基准的倍数。已有 JFR 可指出水系、基础地形、群系/气候和装饰的热点，但样本不等于精确耗时占比。

## 设计时成本链（A/B 前）

1. 每个区块的 256 根柱先后查询漩涡场、地形、河流、群系和材质；部分函数重复计算极坐标、气候、表层过渡。`TerrainProfile` 的点缓存有帮助，却不能让整块生成共享中间结果。
2. 河流按 64×64 区域建缓存。未命中时会查看周围 9×9 个排水节点；节点又可能触发邻接判定、下游、完整流域、河段和湖岸构建。这种“为一个区域按需求完整流域”的冷启动成本，在新区域生成时容易放大。
3. 一个河流区域建立后，采样仍逐段检查候选河段/湖泊。长河段可跨过许多区域，而当前先按整条 reach 的包围盒入选，再展开所有 segment；结果正确，但候选集合可能过宽。
4. `GlobalDrainage` 和 `WatershedRivers` 的主要缓存入口使用对象级同步。昂贵的未命中计算在锁内执行时，多个区块工作线程可能排队；只增加线程数不能解决串行段。
5. 湖岸构建会生成地形高程网格、求最近排水点，再统计大面积内的水域面积。装饰阶段还要保护河岸/海堤，且必须保留原版和模组地物、结构、生物及水更新。

## 实施路线（按先后及风险）

| 阶段 | 改造 | 理论收益来源 | 地形影响 |
| --- | --- | --- | --- |
| A1 | 河流区域只存确实与该区域采样包围盒相交的 **segment**，建立空间桶/索引；保留现有距离判定和顺序 | 大幅缩小每柱的河段候选数 | 应可逐位一致 |
| A2 | 湖岸的最近排水点查询加空间索引；面积统计用双线性单元的上下界跳过全同号小格，混合格仍逐点计数 | 减少流域初建成本 | 应可逐位一致，须先证明边界条件 |
| A3 | 生成一个区块时建立 16×16 柱快照及必要的海堤 halo，统一复用漩涡坐标、基础地形、水系、气候、材质参数；现有点查询 API 保持可用 | 消除同一柱在填充、群系、装饰保护中的重复求值 | 应可逐位一致 |
| A4 | 用每柱的材质计划取代每个 y 方块重新判断沙、岩、层带；将漩涡场和起伏所需的共同极坐标/噪声中间值融合 | 降低 512 高度范围内热循环的常数成本 | 应可逐位一致，注意浮点运算顺序 |
| B1 | 将全局排水/河流缓存改为短临界区与计算锁分离；对最昂贵的单个流域/区域做受控 single-flight，缓存有容量与生命周期限制 | 消除不同区块的长时间锁等待和重复冷启动 | 结果不变，并发风险较高 |
| B2 | 预编译每群系的装饰阶段和地物引用；在注册表/数据包重载后失效。保护区先用区块级安全掩码判定，只有边界再调用精确规则 | 降低每次地物尝试与结构判定的固定开销 | 原版/模组装饰语义不变 |
| C | 若 A/B 后仍明显高于目标，才对**远离河岸、海堤、断崖、雪线和峰顶**的低曲率区采用自适应稀疏采样；保留全分辨率碎裂边缘与局部细节噪声 | 降低高成本地形样本数 | 可接受轻微变化，需要新生成版本及视觉验收 |

### A 阶段：先减少无效工作

优先做 A1，因为它只改变候选集合，不应改变任何一点的河流结果。入桶条件必须比原采样判定**更宽或相同**，不能因空间索引漏掉河边缘、支流转弯或湖口；保存确定性遍历顺序。A2 中双线性插值的值不会超出四角的最小/最大值，只有能证明当前面积计算完全符合这一模型时才可整格跳过，否则回退到旧算法。最近点索引也须处理等距时的原有优先级。

A3 的快照应仅属于当前区块生成任务，不建立无限增长的全世界柱缓存；跨区块邻居从已有有界缓存查询。海堤和地形边界需要 halo，不能用块内数据截断 3 格边界。A4 须谨慎处理 `double` 的求值顺序、不同高度的地层/矿物条件与水体后处理；逐位一致性是合入条件。

### B 阶段：水系求值重新组织，而非改掉水系

`GlobalDrainage` 的站点、邻居、下游、流域，与 `WatershedRivers` 的模型、区域缓存有依赖链。先画出依赖图，再一次只改一个缓存：锁只保护查找/发布/淘汰，耗时构建放到锁外；可能出现同键并发构建的对象采用 single-flight。不能让下游等待上游，而上游又反等下游；递归流域构建要有明确的无环顺序或回退路径。缓存应按世界种子/维度隔离、有容量上限、支持重载清理，并记录命中、未命中、计算时间与锁等待（默认不开高频日志）。

这一步比简化河流算法优先：维持连续主干与支流、基于群系温度的径流/蒸发、自然河岸、冰河条件和湖泊水量。对并发改造要特别检查生成顺序不同、四线程冷启动和跨区块边界的一致性。

B2 不应通过少尝试树、矿物、结构或模组地物“优化”数字。装饰的安全掩码只对能证明安全/不安全的区域走快路，未知模组地物和动态高度规则走原路径。结构 `/locate`、生物群系选择与生物生成维持原规则。

### C 阶段：只有精确改造不够时才损失少量质量

候选是按坡度和局部曲率自适应采样，而不是一律把所有噪声网格粗化。河流、水边、岛缘、干旱平顶山/粘土山边缘、山峰、雪线与中心 7×7 区域永远走原精度；低变化的内陆缓坡可先以 4 格间距试验，若插值估计超过预设误差（建议高度 1 格）立即回退精确采样。保留一层便宜的全分辨率细节以避免再次出现“过于平滑/函数感”。这属于候选设计，并未证明能达到误差界或性能目标。

任何实际改变已生成地形几何的优化，必须显式升级生成版本，支持旧存档的 V5 路径或提出清楚的迁移策略，并检查新旧区块拼接。当前 512 高度包含高山；直接缩到主世界常见的 384 高度会截断地形并破坏存档兼容，不列为近期方案。减少水的后处理标记也可能让河流重新变成不流动，因此不作为捷径。

## 设计时拟定的判定门槛

- 每完成 A1、A2、A3/A4、B1、B2 各有一次独立对照；先检查结果正确，再看同条件新区域的 FULL 区块时间、线程 CPU、锁等待、分配量和长时间旅行后的缓存占用。单次好结果不下“已接近主世界”的结论。
- A/B 应保持固定种子的原始地形/河流指纹和海堤 ≥3 格、自然流水、河网连通、水量、湖岸/雪线等验证；装饰阶段保留地物尝试与结构、生物、模组群系兼容性。若浮点逐位一致不现实，应解释差异并按 C 阶段的视觉标准审查。
- 在同版本、同模组、同种子、同位置与相同冷/热条件下成对测量主世界和第四层，覆盖不同漩涡臂、海洋、沙漠、山区、中心边缘；看中位数和慢区块尾部，而不只看平均吞吐。Forge 与 NeoForge 分开下结论。
- 若 A/B 仍高于 1.5 倍，按新 JFR 的真实剩余热点决定是否做 C；若 C 使海岸、河流或群系边缘重新变得光滑，即便跑分提高也要回退。因原版地物/结构和更大世界高度带来的固定成本，最终可能无法稳定达到 1.5 倍，应如实记录边界。

A1/A2、按区块复用的 A3、材质与漩涡中间值的 A4，以及 B1/B2 均已接入；正常主世界速度对照见实测报告。C 保持未实施，不能仅凭正确性检查推断性能目标已达到。
