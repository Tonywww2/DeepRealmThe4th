# 世界生成性能 A/B 优化：实现与验证

日期：2026-09-28。仅实现设计稿中的 A/B 精确路径；没有启用 C 的降精度地形。后续 FULL 区块与模型性能测量见 `docs/世界生成性能A-B优化-实测报告.md`，不要用本文件的正确性结果代替性能结果。

## 已实施

| 阶段 | 改动 | 结果不变的依据 |
| --- | --- | --- |
| A1 | 河流 tile 只保留包围盒与 tile 相交的 segment；先前 reach 筛选和段顺序保留 | 删掉的 segment 不可能通过同一采样包围盒检查 |
| A2 | 湖泊最近站点从 9×9 缩到可证明覆盖最近点的 5×5；水域面积整格同号时直接计数/跳过，异号格仍逐块计算 | 保留原距离、等距优先级和双线性块中心判定；增加穷举对照 |
| A3 | `TerrainProfile` 增加有界区块柱快照，NOISE 与 SURFACE 阶段复用；建快照时用按需 3 格 halo 缓存原始柱 | 仍由同一个 `sample`/`raw` 规则产出柱；halo 不截断海堤邻域 |
| A4 | `TerrainMaterials.MaterialPlan` 把海底斑块、沙滩、河床沉积等噪声判断移到每柱一次；漩涡场的 `sample` 和 `relief` 共用极坐标变换；计算原始底部时跳过无关群系选择 | Y 相关的矿物、层带、雪/冰与后处理仍按原条件逐层判定 |
| B1 | 排水站点、边、下游、流域及河流模型/tile 使用有界 single-flight 缓存；只在查表/发布/淘汰时持锁，复杂计算在锁外 | 同键并发未命中共用一次计算，失败移除，根路径压缩及确定性数据流保留 |
| B2 | 每群系的已解析地物阶段和结构阶段按注册表身份缓存；装饰保护共享 3×3 邻域的懒加载柱，并复用写入坐标对象 | 地物/结构的阶段顺序、种子、尝试次数和保护判断未主动删减 |

主要文件：`worldgen/hydrology/{SingleFlightCache,GlobalDrainage,WatershedRivers,LakeMask}.java`、`worldgen/terrain/{TerrainProfile,BaseTerrain,VortexField}.java`、`worldgen/surface/{TerrainMaterials,BiomeDecoration,DecorationGuard,StructureDecoration}.java`、`worldgen/SpiralChunkGenerator.java`。

这次没有修改生成版本、维度高度、河网算法、海堤宽度、原版/模组地物数量或流水后处理。所有新缓存都属于一个生成器/地形对象，区块快照最多保留 128 块；注册表更换时重新建立地物阶段索引。并发缓存只允许进行中的少量项暂时超过容量，完成后即淘汰。

## 已执行的正确性验证（非性能基准）

- Forge 与 NeoForge 的 `compileJava testClasses --offline` 成功。该命令只验证双端编译与测试类编译，不等于服务端实地生成通过。
- 两端独立 Java 世界生成检查成功：地形 228,933 项；水系/并发/跨区块约 65 万项；湖岸距离 127,008 项与原算法逐位一致，块中心面积 1,968,128 个点与逐块算法一致。
- 湖泊最近站点在三种种子、完整候选网格上与原 81 站点穷举一致；四组固定区域的地形指纹保持为 `9bf55fe4b239594d`、`4baf5c169670f562`、`4014819288fccc39`、`b03a282165f99956`，同时核对了 65,536 根柱的区块快照与逐点查询。
- 水系检查仍见 24 个被接受的流域、185 条河段、4,715 个湿柱、零相邻漏水、三个连通水体；四线程顺序无关性检查通过。这些是模型验证，不代替游戏内流体或地物实地验证。

## 尚未证明的部分

性能对照现已另行完成，但没有单独量出线程锁等待或长期旅行后的内存占用，也没有查看本轮地物/结构尝试数或流体 tick。材质按柱计划已双端编译，但尚未与改造前的逐块方块输出做完整逐位对照。**不能因为模型指纹一致就声称装饰后的整个世界逐位相同**。

若用户仍遇到游玩时生成卡顿，下一步应针对代表性的纯陆地/河网区域测 p95 区块延迟、锁等待和内存，并核查地物/结构统计及实际流水；只有真实瓶颈仍明显时才考虑新的精确优化或 C 的画质折中。
