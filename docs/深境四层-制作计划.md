# 深境四层：维度制作计划

依据：`C:\Users\Tony\Downloads\深境四层.txt`。

项目：DeepRealmTheForth；目标版本为 Minecraft 1.20.1 / Forge 47.4.0，以及 Minecraft 1.21.1 / NeoForge 21.1.233。

状态：已开始实现第一版原型。螺旋地形、四组基础生态、群系 tag 与调试入口已落地；以下仍是完整阶段目标，不表示全部验收完成。当前进展、运行证据和剩余项见 [实现与验证记录](实现与验证记录.md)。

## 1. 目标与范围

制作一个以 `(0, 0)` 区块为中心、向内顺时针收缩并下沉的螺旋维度。地形共八股，奇数股承载四种生态，偶数股为空；所有陆地下方最终通向虚空。

| 股号 | 设定要求 | 首版内容 |
| --- | --- | --- |
| 1 | 干旱类群系 | 沙漠、恶地、台地与峡谷；部分群系交界处出现河流 |
| 2 | 虚空 | 不生成天然实体地形或流体 |
| 3 | 下界、火山 | 下界风格群系、玄武岩地貌、火山锥、火山口与局部熔岩 |
| 4 | 虚空 | 同 2 |
| 5 | 常规温带、热带群系 | 平原、树林、森林、雨林与山脉 |
| 6 | 虚空 | 同 2 |
| 7 | 海洋类群系 | 海岸、浅海、深海与岛屿 |
| 8 | 虚空 | 同 2 |

首版交付包含：可进入的维度、完整螺旋地形、四组生态、基础装饰与生物生成、tag 扩展接口、双版本验证。进入方式先提供管理员调试命令和安全落点；正式传送门、专属怪物、任务与遗迹作为后续内容单独设计。

## 2. 原文未限定部分的初始方案

以下是制作原型时采用的可调默认值，不将其视为原文已经确定的设定。

| 项目 | 初始方案 | 理由 |
| --- | --- | --- |
| 精确中心 | `(0, 0)` 区块几何中心，连续坐标 `(8, 8)` | 区分“中心区块”和“原点方块” |
| 旋转方向 | 从上方俯视，沿陆地股由外向内行进时顺时针旋转 | 明确判断顺逆时针的观察方式 |
| 八股宽度 | 四陆四空交替；按后续确认改为陆地每股 67.5°（3/16），虚空每股 22.5°（1/16） | 陆地总占比约 75%；保留中心空洞及边缘留白 |
| 旋转强度 | `twist=1.44`，初版 0.72 的两倍 | 同一径向区间内的绕转角度翻倍 |
| 急降范围 | 距中心约 64 格，过渡带先试 48～80 格 | 4 区块约为 64 格；避免用硬切面形成环形台阶 |
| 中央终点 | 半径约 16 格内逐渐收束为空洞 | 给急降地形留出空间；不把整个 64 格范围直接挖空 |
| 世界尺度 | 单个漩涡持续向外延伸，外部基准高度逐渐趋稳 | 保持唯一中心，并避免外圈超过世界高度上限 |
| 初始世界高度 | `min_y=-64`、`height=512`，上界 Y=447 | 为漏斗落差和山脉保留空间；性能与视觉测试后定值 |
| 种子 | 中心、股序和方向固定；种子改变局部地形与群系分布 | 每个存档保留同一世界概念，同时有探索差异 |
| 下界属性 | 全维度 `ultrawarm=false`，3 股通过群系、方块与地形表现下界 | 7 股需要正常海水；超热属性不能只对一个股设置 |
| 海水边界 | 天然岸堤、实体海床与分级盆地承接水体 | 满足偶数股为空的要求，避免天然水幕铺满虚空 |

开始开发后，先用俯视预览和游戏内原型校准螺旋松紧、世界尺度、落差与水体观感，再固定第一版参数。

## 3. 螺旋与高度模型

### 3.1 使用同一套空间计算

建立共享的 `SpiralLayout`，输入世界 X/Z，输出半径、股号、距股边缘的距离及中心过渡系数。区块生成器、群系分配、河流、海床、装饰与调试工具全部调用它。

建议用对数螺旋作为初始模型：

```text
r = hypot(x - centerX, z - centerZ)
theta = atan2(z - centerZ, x - centerX)
phase = wrap(theta + twist * ln(max(r, coreRadius) / referenceRadius) - rotation)
pair = floor(phase / (PI / 2))
local = phase - pair * (PI / 2)
arm = pair * 2 + (local < (PI / 2) * landFraction ? 1 : 2)
```

这里采用北方为 -Z、东方为 +X 的俯视坐标；`twist > 0` 时，同一股向内追踪的角度增大，对应顺时针。股号绑定螺旋带，并不永远绑定一个罗盘方向。

当前 `landFraction=0.75`、`twist=1.44`。每个陆地/虚空对合计 90°，分为 67.5° 陆地与 22.5° 虚空；边缘距离和股中心点均按不等宽区间计算。

实现时必须检查角度在 0/2π 处的连续性、负坐标和中心除零问题。所有空间判断使用世界坐标；`BiomeSource` 的四分之一方块坐标先转换回方块坐标，避免急降半径被放大四倍。

### 3.2 高度、厚度和虚空分别控制

- 径向基准高度采用有上限的平滑曲线：外圈缓升、向内明显降低，64 格附近叠加急降段。
- 叠加各生态的山脉、峡谷、岛屿等局部起伏。越接近中心和陆地边缘，局部噪声振幅越小，保证螺旋主轮廓可辨。
- “越往中心越低”约束宏观基准曲线；山峰与峡谷不要求逐方块严格单调。
- 陆地必须同时拥有上表面和下表面。厚度随半径、边缘距离变化，底部自然收尖；不生成封底基岩。
- 偶数股使用明确的虚空判定，不依赖稀疏噪声碰巧生成空气。少量边缘扰动不得使两条陆地股相连。
- 洞穴放在后续阶段，限制在有足够厚度的陆地内部，并避开海床、河床与急降区。

## 4. 生成器与代码组织

建议采用自定义 `ChunkGenerator` 和 `BiomeSource`，把螺旋几何、地形轮廓和群系选择保留为独立算法。这个维度既有有限厚度陆地，也有严格虚空和局部水位，需要直接控制这些规则。

| 模块 | 职责 |
| --- | --- |
| `worldgen/layout/SpiralLayout` | 螺旋股号、边缘距离、中心距离 |
| `worldgen/terrain/TerrainProfile` | 上下表面、核心材料、局部水位、密度采样 |
| `worldgen/biome/SpiralBiomeSource` | 四组候选群系、亚区域分配、群系全集 |
| `worldgen/SpiralChunkGenerator` | 区块填充、表层、heightmap、装饰与生成阶段协调 |
| `worldgen/surface` | 干旱、下界、温热带、海洋的基础材料和表层规则 |
| `worldgen/hydrology` | 河网、分级海盆、河床海床与流体约束 |
| `platform/worldgen` | 两版本 Codec、注册、生成回调和查询接口的差异 |
| `platform/commands` | 维度进入、返回与采样诊断命令 |
| `data` | 维度定义、群系 tag、地形配置和兼容配置 |

实现约束：

1. `fillFromNoise`、`getBaseHeight`、`getBaseColumn` 使用相同采样规则；高度查询需区分海面和海床。否则出生点、树木和结构可能悬空。
2. 每个生成器持有自己的不可变参数与噪声实例；世界种子接入实际生成上下文，并验证保存、重启后能复现，不把种子写死为 0，也不用全局静态变量传种子。
3. 复用原生可用的装饰和生物生成流程，但对虚空边界、地形承载能力与结构适用性增加约束。自定义生成器不会自动获得所有原版噪声生成器行为。
4. 装饰阶段也必须遵守虚空范围。跨区块树木、矿脉、熔岩泉等要做边界验证；不能只在基础填充阶段留空，也不能靠运行时反复删块修复。
5. 首版天然结构采用明确白名单；未经适配的巨大结构和专用生成器依赖不作为默认兼容承诺。

## 5. 群系 tag 与兼容机制

建立本模组自己的四个稳定入口，两个加载器使用同一套名称：

```text
deeprealm_4th:region/arid
deeprealm_4th:region/infernal
deeprealm_4th:region/temperate_tropical
deeprealm_4th:region/oceanic
```

文件放在 `data/deeprealm_4th/tags/worldgen/biome/region/`。再细分荒漠、恶地、山地、雨林、海岸、浅海、深海、岛屿和河流用途，避免一个大候选池造成海岸与深海随机拼贴。

候选群系由 tag 提供；分布权重、温湿度偏好、适宜坡度和地形类型由独立的群系配置提供。先划分生态亚区域，再在对应 tag 内选择群系；未知外部群系使用所属大区的保守默认配置。

兼容接入分两层：

- **选择层**：把模组群系加入 tag 后，它能被维度选中，并保留其群系身份、颜色及可兼容的生物和装饰设置。
- **地貌层**：外部模组专有的表层规则、地形生成器、特殊结构或独立维度机制，需要兼容配置或代码适配；单加 tag 不会自动移植这些行为。

外部群系引用使用 `required:false`，数据包默认 `replace:false`，不安装对应模组时仍能加载。这与 [Forge 官方 tag 机制](https://docs.minecraftforge.net/en/1.20.1/resources/server/tags/)一致。

加载时校验空 tag、重复成员和失效配置。每个大区保留原版备用群系，并输出可定位的诊断；`possibleBiomes` 必须覆盖所有可能返回的群系，包括河流及虚空占位群系。虚空股仍需要合法的群系数据，可采用不带装饰的虚空群系，但这不产生实体地形。

禁止为本维度的需求直接全局修改被复用的原版群系，以免影响主世界和下界。新增特有装饰优先使用维度内生成逻辑或本模组专属群系。外部装饰需检查 feature 排序循环，这类错误会使世界生成崩溃，见 [NeoForge 官方说明](https://docs.neoforged.net/docs/1.21.1/worldgen/biomemodifier/)。

群系池和地形配置按存档版本管理；修改后重启并在新世界或新生成区块验证。增加 tag 成员可能改变新地块分布，不承诺 `/reload` 能让旧区块同步改变。

## 6. 四组生态的具体制作顺序

### 1 股：干旱带

先做沙漠、恶地、岩石台地三类基本轮廓，再加入峡谷侵蚀。沙层采用稳定基底，避免裸露悬空的重力方块在更新后大面积坍塌。

河流由“群系边界带 + 连续河网 + 坡度/集水条件”共同决定，只让部分交界段出现河流。河床和两岸必须真实切入地形；河道向低处连接，不让每条群系边界都成为等宽水渠。首版河流在进入虚空前收束到陆地内的盆地。

### 3 股：下界与火山带

使用下界荒地、玄武岩三角洲等作为默认群系候选。火山另做地形：火山锥、凹陷火山口、熔岩池和有限的熔岩沟，不能只替换群系名称。

先完成无遮挡的下界地貌；大型菌类、洞穴和复杂熔岩喷泉在基础流体测试后接入。下界群系的装饰可能依赖原有高度与基底，需要逐项验证。

### 5 股：温带、热带带

由大尺度温湿度和地形分区组织平原、森林、雨林与山脉。靠近山地的群系跟随山脉分布，树木只落在有稳定地面的范围内。山脉振幅受剩余世界高度限制。

### 7 股：海洋带

海洋必须有实体海床，海床下方仍为虚空。按海床深度与距岸距离生成海岸、浅海、深海和岛屿，并与群系选择共用参数。

推荐首版采用沿螺旋下降的分级海盆：每个海盆内部水平水面，相邻海盆用天然岩脊、岸堤和受控河道连接。这样既能随整体地形降低，又能避免把海面做成随每列高度变化的斜坡。

水体稳定性是独立验收项：跨区块接壤、重新加载和流体 tick 后，天然水源不应进入偶数股。若以后希望加入流入中央深渊的大瀑布，应明确将其列为“虚空允许天然流体”的设定变更，再设计范围和性能预算。

## 8. 验收与性能

### 算法和区块验收

- 在多组半径处绘制八股分布，并沿单股追踪，验证向内顺时针；特别覆盖负 X/Z、角度接缝和中心。
- 径向剖面覆盖约 16、32、48、64、80、128、256、1024、4096 格，确认中心急降与外围平缓。宏观曲线与局部噪声分别验收。
- 同种子、同配置、同版本重建一致；按不同区块生成顺序生成同一区域，结果一致；相邻区块无接缝。
- 不同种子改变局部细节；两游戏版本保持宏观布局一致，不要求原版/外部装饰逐方块一致。
- 纯虚空区在完成装饰和流体更新后仍无天然方块/流体；陆地下方无基岩封底。玩家主动搭建和倒水不属于天然生成约束。
- `getBaseHeight`、`getBaseColumn` 与实际生成的表面、海床和空列相符；重启后不漂移。

### 运行与兼容验收

- 两版使用独立的新测试存档；以服务器日志到达 `Done`、维度区块真正生成且无异常为依据，不能只看 Gradle 的 `BUILD SUCCESSFUL`。
- 验证安全进入、返回、死亡后重生与重连；在崖边、海上和中心执行进入命令时均有正确落点处理。
- 使用至少三个种子检查默认群系；以一个测试群系证明“只追加 tag 即可入选”，再以选定的真实外部群系模组验证实际装饰兼容。
- 覆盖空 tag、可选模组未安装、外部群系不含定制表层、装饰越界和 feature 排序冲突等情形。
- 客户端检查螺旋可辨识度、断崖、海床、岛屿、河流和山体；默认渲染距离无法完整显示巨型漩涡时，使用生成器采样预览辅助总览。

### 性能原则

按区块或列缓存空间采样；tag 与群系配置在生成器初始化时解析，不在每个方块生成时反复扫描。完整虚空区块跳过实体填充；陆地只遍历实际厚度，昂贵的三维噪声按需要计算。

在相同机器、JDK、种子和生成范围下记录每秒生成区块数、单区块耗时分位数、峰值内存，以及水体更新稳定后的 tick 耗时。先取得 P1 基线，再对比 P2～P5；性能门槛根据实测确定，不预先承诺固定倍数。

## 9. 数据与双版本维护

- 维度 ID 暂定 `deeprealm_4th:fourth_layer`。
- 共用维度语义、螺旋数学、群系 tag 名称和地形参数；加载器注册及 Minecraft API 差异集中在 `platform`。
- Codec/MapCodec、区块填充签名和注册类型以项目实际依赖为准。已检查本地 NeoForge 21.1.233 源码；实现 Forge 侧时继续核对 47.4.0 对应接口。
- `dimension_type` 与生成器声明的高度保持一致；跨版本 JSON 字段按实际解码验证。两版共同可用的怪物光照配置可先用整数，减少 IntProvider 对象格式差异。
- 若需要 biome modifier，Forge 与 NeoForge 使用各自目录和类型命名；配方、战利品等扩展内容使用各版本正确的单复数目录。
- 模组资源包与独立数据包分别核对 pack format，不把 1.21.1 的资源包格式值当成所有数据包格式值。
- 地形参数保存在可序列化的世界生成配置中；改变算法或群系池时记录版本，并注明只影响新生成地块。测试优先新建世界。

## 10. 首个可评审成果

先交付 P0 + P1：一张带股号的俯视分区预览、一张径向高度剖面图，以及两版都能进入的纯石头螺旋维度。

这个成果应当能直接判断“八股是否像设定的漩涡”“向内是否顺时针”“四区块附近是否有足够明显的急降”“虚空比例是否合适”。确认这些空间关系后，再推进水体与生态内容。

本计划采用 `MC-Dev-Skills` 的维度生成、群系、跨版本和运行验证约定，特别是统一地形查询、隔离平台差异，以及以实际区块生成而非仅编译作为验收依据。
