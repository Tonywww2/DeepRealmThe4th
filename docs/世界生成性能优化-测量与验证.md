# 世界生成性能优化（2026-09-28）

## 范围和策略

用户允许轻微的质量损失。第一轮先移除已测量到的重复计算，不降低地形采样精度，也不跳过原版/模组地物、结构、生物或流体更新。保持 V5 地形及完整流域规则，保留其他正在进行的项目改动。

1. 固定种子 42，以相同的四组坐标测量纯地形计算和实际 FULL 区块生成。
2. 用 JFR 定位热点，优先优化重复群系计算和湖岸距离计算。
3. 对照地形指纹、湖岸逐位一致性、河流水量和连续性；双端编译及实际生成验证。
4. 只有仍有明显瓶颈时才考虑质量折中；性能报告不将模型采样耗时等同于游戏帧率。

## 基准方法

- `scripts/Benchmark-Worldgen.ps1 -Loader forge -Label baseline`：纯 Java，四个 8×8 区块范围，三轮独立模型及一次四线程查询。
- 历史实际服基准曾使用专用世界生成命令；该测试命令现已移除。记录使用无玩家、seed=42 的独立 `verification-world-vortex-v13-perf-baseline` / `optimized` 存档（允许数字后缀）。先预热 16 个其他区块，再请求 256 个目标 FULL 区块，原生依赖范围也正常生成。
- 必须使用全新存档，不能比较已经生成过的区块。报告在 `run/<loader>-server/worldgen-performance/<save>/`。
- JFR 包括预热及计时后的地形指纹查询，不包含原始填充一致性测试；报告中的 `totalMs` 只计四个目标范围的 FULL 请求。区块依赖和 JVM 热身会影响单次结果，应区分观测值与稳定提升幅度。
- 基线 Forge：6,241.94 ms，41.01 个目标区块/秒；436 个装饰区块、20,683 次地物尝试、无地物异常。地形指纹 `b28d9f7d8a9e9ed9`。
- 基线 JFR 中，群系选择调用链有 81 个执行样本，湖岸构建 18 个；这是热点定位，不是精确百分比归因。

## 第一轮实现

- 每个群系源/工作线程保留有界的 4,096 个精确 X/Z 群系结果。Y 本来不参与选群系，不再因每层 quart 查询而重复执行气候噪声；哈希冲突会重新计算，不复用错误坐标。
- 群系注册键字符串在注册表绑定后缓存，避免每次比较反复创建字符串和重新计算字符串哈希。
- 湖岸距离由“每个网格遍历所有岸线点”改为分行最近 X + 有界 Z 搜索。仍使用原来的 hypot 查表和 64 格距离上限，结果逐位一致。
- 基础柱查询直接填充空气，只对真实实体/流体高度范围计算材质。
- 按 MC-Dev-Skills 的原版路径验证原则，对照本地 Forge 1.20.1 字节码及 NeoForge 1.21.1 源码中的 `NoiseBasedChunkGenerator`：NOISE 阶段先获取区块节调色板所有权，再直接写入 section，在 finally 中释放。不用于玩家操作或装饰写入；后续 INITIALIZE_LIGHT 和河流后处理标记完整保留。
- 柱体自顶向下填充，每个高度图只更新第一次命中的最高有效方块，避免每个方块反复推进高度图。用内存中的真实 ProtoChunk 逐块核对公共材质查询、基础柱查询、海底/表面高度图。
- 山脊方向和长度预计算；用保守包围盒跳过贡献必为零的山脊，保留投影公式和浮点计算顺序。噪声的保守范围保证不会裁掉有效山坡。
- 同一区块各装饰阶段复用 3×3 邻域的保护信息；结构仍使用自己的嵌套保护规则，并保持原有阶段、随机种子和地物尝试次数。

## 已测性能（固定工作量，不是 FPS）

| 测量 | 修改前 | 最终修改后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 纯地形，7 轮串行总耗时中位数 | 273.39 ms | 215.36 ms | 21.2% |
| 纯地形，4 工作线程单次 | 205.49 ms | 167.37 ms | 18.6% |
| Forge，256 个目标 FULL 区块 | 6,241.94 ms | 5,315.45 ms | 14.8% |

串行每轮为 65,536 柱、新建模型；七轮保留 JIT 冷热变化，不丢弃慢样本。复测直接运行保留下来的基线 class 与优化 class，使用相同 JVM 内存参数、同一份注册表气候快照、无 JFR。原始数据位于 `build/reports/worldgen-performance/forge/{baseline-repeat,optimized-repeat}/timing.txt`。

完整生成基线在 `run/forge-server/worldgen-performance/verification-world-vortex-v13-perf-baseline/runtime.txt`，最终结果在 `verification-world-vortex-v13-perf-optimized-3/runtime.txt`。吞吐由 41.01 增至 48.16 个目标区块/秒。该对比是一次固定场景观测，并非所有种子、模组包和硬件的稳定保证；未测客户端帧率。

中间迭代也保留：只改群系缓存/湖岸时为 6,958.28 ms，加入批量填充后为 5,907.47 ms。没有用纯算法变快来代替完整生成验证。最终 JFR 中原版矿物放置、调色板、光照及调度仍占明显份额，因此整体收益小于模型收益；这轮没有减少矿物、地物或结构来扩大数字。

- Forge 与 NeoForge 的 `build`、`verifyHydrology` 均通过，包含 Astral 原有测试，未撤销其他开发改动。
- 每端当前地形断言 228,933 项，水系断言 572,520 项；127,008 项湖岸距离与旧遍历算法逐位相同。
- 四个区域的离线指纹及多线程指纹与修改前一致；Forge 完整生成地形指纹仍为 `b28d9f7d8a9e9ed9`。
- Forge 原始填充：1,179,648 个方块、4,608 项高度、2,304 项缓存/未缓存群系选择检查全部通过。
- 最终 Forge 仍为 436 个装饰区块、20,683 次地物尝试、45 次结构区块放置、零地物异常。原生地物成功报告数存在 1 次差异，因此不声称装饰后的整个世界逐块相同。
- Forge 自然流水：1,875 柱、1,364 个河床柱；测试未额外安排流体 tick，稳定后有 101 个流动水方块，零漏水；本次 27 个强加载区块已释放。
- Forge 群系检查：30 个条件满足的群系、90 个已存储 quart 单元通过。当前自然样本没有命中满足条件的冰冻河流；温度检查的 64 柱独立寒冷夹具通过，不将未命中表述为自然冰河验证成功。
- NeoForge 实际新存档：256 个目标 FULL 区块 5,476.40 ms；没有 NeoForge 修改前的完整生成基线，因此不据此声称其提升百分比。与 Forge 相同的地形指纹、1,179,648 个原始方块、4,608 项高度、2,304 项缓存选择均通过。
- NeoForge 的 21,609 项注册表气候比较、64 柱寒冷夹具、中心/海堤检查通过；自然流水 784 tick 后同样为 101 个流动水方块、零漏水。已释放 27 个测试强加载区块。
- 两端测试服务器均已正常保存并关闭；NeoForge 的临时 `level-name` 设置已恢复。测试存档及 JFR 报告保留供复查，没有删除玩家存档。

## 使用和限制

不需要更换存档、重置种子或更改生成版本；优化作用于后续生成/查询，不会重写已经生成的区块。本轮没有降低采样精度或改变地形参数，核心地形质量无主动降级。

基准命令会阻塞测试服主线程，日志中的 `Can't keep up` 在此工作负载下是预期现象；不要将它当成日常游戏流畅度测试。所有性能命令都仅允许指定的无玩家 seed-42 测试目录，失败后也必须换新存档，避免把已生成缓存当成优化成果。
