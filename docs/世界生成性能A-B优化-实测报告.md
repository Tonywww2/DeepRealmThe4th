# 世界生成性能 A/B 优化：实测报告

日期：2026-09-28。测试对象为 A/B 已接入、C 未接入的代码。所有 FULL 对照均为同一模组开发服内、相同 seed=42、四组各 8×8 个**新**目标区块（每维度共 256 个）；每组先请求 FULL、随后重复请求缓存区块，将两次耗时之差作为“估算生成耗时”。这个差值仍包含区块邻域依赖、装饰、调度及命令测量误差，并非精确 CPU 时间或客户端 FPS。

## FULL 区块：相对正常主世界

| 加载器与独立存档 | 生成顺序 | 正常主世界估算 | 第四层估算 | 第四层/主世界 |
| --- | --- | ---: | ---: | ---: |
| Forge 1.20.1，A | 主世界先 | 20,097 ms | 10,634 ms | **0.529** |
| Forge 1.20.1，B | 第四层先 | 20,623 ms | 10,247 ms | **0.497** |
| NeoForge 1.21.1，A | 主世界先 | 10,405 ms | 5,418 ms | **0.521** |

三个存档的主世界均使用 `minecraft:normal`/噪声生成，而非超平坦。Forge 反向顺序的结果与首轮接近，减轻了“先生成哪个维度”造成的疑虑。Forge 与 NeoForge 的 Minecraft 版本、区块调度与运行时不同，**不应横向比较两端的绝对毫秒数**。在所选区域和环境中，第四层已低于正常主世界的 FULL 区块耗时；不能推广为所有种子、区域、模组包或在线游玩场景都更快。

## 超平坦参照：不能混作正常主世界

旧 Forge 对照存档经 `level.dat` 检查确认为超平坦：旧记录主世界 1,684 ms、第四层 6,841 ms、比值 4.06；本轮新超平坦存档主世界 3,749 ms、第四层 10,355 ms、比值 2.76。原始文件分别是 `build/reports/worldgen-performance/forge/overworld-comparison.txt` 与 `overworld-comparison-ab-flat-20260928a.txt`。

比值下降，但本轮两边的绝对耗时都比旧记录高。可能涉及 JVM 热身、系统负载、依赖区块/存储与同时进行的开发活动；仅凭这两次 FULL 结果**不能量化 A/B 对整服生成的净提升**。超平坦主世界本身也不是本项目“接近原版主世界性能”的合适参照。

## 同环境重跑旧字节码：纯地形模型

保留的 `optimized-final/classes` 为 A/B 前的世界生成字节码；用相同 Java 17、`-Xms512m -Xmx1G`、同一气候快照和同一模型基准入口，与当前代码交错运行两轮，每轮 7 次串行、1 次四线程；都**未启用 JFR**。四个区域的地形指纹在旧/新字节码间完全相同。

| 固定工作量：四组区域 | A/B 前 | A/B 后 | 描述性变化 |
| --- | ---: | ---: | ---: |
| 串行热态，12 次总耗时的中位数 | 219.56 ms | 210.70 ms | 约低 4.0% |
| 四线程单次总耗时，两轮均值 | 169.05 ms | 111.46 ms | 约低 34.1% |
| 冷态首轮总耗时，两轮范围 | 302–307 ms | 282–355 ms | 波动重叠，不能断言改善 |

这支持“移出水系缓存长锁”改善了并发模型查询，但它只计算地形柱，不包含游戏内填充、原版地物、结构、光照、保存和区块调度。两轮样本不足以作统计置信区间，也不能将 34% 直接套到 FULL 区块时间上。

原始文件位于 `build/reports/worldgen-performance/forge/ab-{old-rerun,current}-20260928{a,b}/timing.txt`。当前代码的两份编译字节码保存在对应 `ab-current-*/classes`；旧字节码继续保留在 `optimized-final/classes`。

## 解释与限制

- 三组正常主世界结果都达到了原方案提出的“同场景 ≤1.5 倍”的速度目标，但这是一组区域的一次或两次服务端测量，不是稳定性能保证。
- 第四层有虚空区域，正常主世界一般持续生成实体地形、洞穴、含水层等；相同 X/Z 区块数并不代表相同方块与地物工作量。若关注满负载陆地区域或游玩时卡顿，应另按代表性区域和 p95 区块延迟测试。
- 本次没有在旧 A/B 字节码上重跑**正常主世界 FULL 区块**，所以不能严谨地说 A/B 让完整生成提升了多少。模型并发收益明确，整服收益仍待隔离对照。
- 此次是服务端区块生成测试，不是客户端 FPS、TPS 长时间稳定性、内存峰值或多人联机测试；没有做新的地物/结构/流水视觉检查。
- 测试脚本按标签拒绝覆盖报告，所有目标均为新存档；每组 `forceload` 在 `finally` 中释放。两端测试服已正常保存并停止，`server.properties` 的原始超平坦测试配置已恢复。新测试存档与报告保留，未删除玩家数据。

结论：**在本次固定区域的正常主世界对照中，第四层约为主世界耗时的一半；A/B 的纯模型四线程耗时约降低三分之一。** 不再以旧超平坦 4.06 倍作为正常主世界性能结论。
