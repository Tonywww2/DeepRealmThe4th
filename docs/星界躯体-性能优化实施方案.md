# 星界躯体性能优化实施方案

## 依据与本轮目标

[Spark 报告](https://spark.lucko.me/zevM457m2a)中，星界躯体装备刷新链占服务端线程采样 54.14%；该链中首次进入 Rhino 的调用占服务端线程 47.37%，包含脚本调用的 Java API。用户已允许降低计算频率，要求由 GPT-6.1-Sol 子代理实现。

本轮已实现可直接使用的降频、计算轮共享及桥接脚本优化。保留 Curios 属性接口与当前规则数值，不引入外部运行库。任意动态 JS 的跨轮结果缓存、详细摘要协议重构不属于本轮：前者需要逐规则依赖声明，后者在本次采样中不是主要热点。

## 结算调度

- 服务端 `calculation.interval_ticks` 默认每 5 tick 重新结算，范围 1–1200，配置为 1 恢复每 tick。正常 20 TPS 时周期约 0.25 秒；短暂条件可能在两次采样之间消失，这是本轮允许降频后的行为。
- 首次装备、替换物品、槽位绑定改变、内容编辑和显式 invalidate 使下一次 Curios 更新立即计算。recalculate 始终强制新计算轮，不受间隔限制。
- 两次结算之间保留上次完整属性快照，继续由 Curios 提供属性；不能在失效时先删除快照造成属性短暂消失。
- 自有容器写入必须标记输入变更；跨容器 PLAYER 效果组也要失效。外部模组绕过写入 API 修改数据时，最迟在下一周期读取新值。
- 运行时状态与玩家会话、槽位、当前物品实例绑定；玩家退出/重生、换物、服务器关闭须清理或安全重建。不得让全局缓存永久保留 Player 或世界。
- 菜单预览也使用相同配置的间隔，内容编辑即时更新。装备刷新与预览不可错误复用不同语义的结果。

## 每轮共享与 Java 开销

- 引擎管理显式计算轮作用域，finally 释放临时 memo；每次 calculate 都是新轮，不能用游戏 tick 代替轮身份。
- 已提供 `.readOnlySnapshot()` 显式契约，以及脚本可使用的 `memoGet` / `memoPut`（阶段与容器隔离）和 `roundMemoGet` / `roundMemoPut`（整轮共享）API，用于共享经过审计的只读数据。resolve、intrinsic 与最终 effective 视图不能混用。
- 任意旧回调继续兼容；共享容器输入等可能改变观察时间的优化须显式选择只读快照契约。公共物品/NBT getter 保持防御性复制。
- 消除不需要属性规则的节点的 medal context 构造、同阶段重复视图及内部标签判断产生的副本。
- 拓扑调度使用反向依赖表，保持格子顺序、循环降级和错误处理结果。
- 不把正在增长的 bases/finals 直接暴露为共享 Map；保留每个上下文创建时的可见结果集合。

## 整合包桥接脚本

目标为本机 SenDimsBanForges 实例的 `kubejs/startup_scripts/astral_gems/20_bridge.js`。实施前检查关联 evaluator，保留所有规则公式。

- reads 只构建元信息和所需几何，省略无用的宝石负载解码、玩家状态查询。
- 坐标查询改为索引，连通搜索使用队列游标；按实际访问惰性生成几何。
- 对同一稳定阶段的 cell DTO、宝石解码和所需状态使用计算轮 memo；共享对象必须在本脚本中只读，不把可变结果/writer 缓存。
- 属性名目录预去重，数值按轮采样；普通 intrinsic 不读取其不需要的完整玩家状态。
- 单次节点解析结果、参数和本地负载尽可能复用，跨节点数据不能被某一条规则修改。
- 不直接在外部目录进行未经检查的覆盖：实现代理先在项目中准备改动文件与原文件摘要，主代理检查后应用到对应脚本，防止覆盖并发修改。

## Rhino 与 Java

不将任意 KubeJS 脚本自动转成 Java 源码作为本轮依赖。JS 闭包、动态对象和 KubeJS 的 Java 桥接会使通用转换引入新的语义问题。继续支持已有 Java ScoreRules/节点 API；本轮将调度、轮次和可复用基础计算放在 Java，脚本保留规则配置及自定义逻辑。已核查 KubeJS Rhino 2001 官方分支，`Context.createCompiler()` 直接返回解释器，CodeGenerator 生成解释器内部字节码；该路径没有自动 JS→JVM 的优化开关。[官方 Context 源码](https://github.com/KubeJS-Mods/Rhino/blob/2001/common/src/main/java/dev/latvian/mods/rhino/Context.java)

## 交付与验证

- 公共逻辑同时服务 Forge 1.20.1 与 NeoForge 1.21.1，版本差异留在 platform。
- 更新开发者指南、KubeJS 类型声明和示例中涉及的新配置/API。
- 只进行双版本编译、相关脚本语法检查，以及针对调度/失效/作用域隔离的最小必要验证。不启动游戏、不追加全量测试或基准测试，不承诺未经复测的提速比例。

## 实施结果与最小验证

- 装备调度使用弱玩家会话和弱物品绑定，记录世界实例、内容 revision 与显式失效代次。自有存储写入会失效同玩家全部装备结算，跨容器 PLAYER 效果组随之更新。菜单拥有独立调度，监听物品和玩家失效。等待期间保留完整属性快照。
- Curios 5.14.1 在相同物品 NBT 变化时也调用 onUnequip，摘要更新须跳过该 hook 的失效；真实绑定替换另由身份检查识别。已对照本地官方 source JAR 的 CuriosEventHandler.tick 确认该路径。
- 引擎 finally 释放 memo、容器副本与容器 namespace。过期 context 的 memo 访问被拒绝。只读契约复用 resolver 阶段视图和容器副本，旧定义仍复制当前容器，bases/finals 的 context 可见集合保持固定。拓扑调度已改为反向依赖表，无属性规则的格子跳过 medal context。
- 本地 pack 的桥接修改版与原文件 SHA256 manifest 放在 `build/reports/spark-zevM457m2a/implementation/`，由主代理核对并部署。新 API 有能力探测回退，旧 JAR 可使用局部脚本优化，新调度与轮共享须更新模组。可维护的通用适配示例已保存在 `examples/astral-kubejs/startup_scripts/astral_round_memo.js`。
- 双版本 `compileJava` 已通过，既有 `buildAllVersions` 已完成双版本打包。打包任务连带编译了既有测试源码，未运行 test/check、游戏客户端或新的 Spark 基准。相关 JS 通过 Node 语法检查。
- 本地 Rhino 2001 最小 Java probe 使用实际 FillerContext memo 方法验证 JS 对象身份与嵌套值往返、旧 API 方法探测回退、计算结束后拒绝访问和新轮隔离。验证 harness 只位于 build 报告目录。未量化运行时提速比例，本机 pack 与采样服务器脚本仍未校验一致。
