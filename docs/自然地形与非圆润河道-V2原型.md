# 自然地形与非圆润河道：V2 离线原型

这是 V2 历史记录。当前 `0.1.6` 已接入 V3 世界生成路径，详见 [V3 接入与验证](全局水系接入-V3工作记录.md)；下文保留 V2 当时的实现边界和未通过项。

开发版本：`0.1.6-prototype2`。依据已确认的[分阶段计划](主干支流水系与群系气候-重构计划.md)，继续阶段 2 的形态实验。**没有替换正式生成器，也未迁移或重生成玩家旧存档；游戏内仍是 0.1.5 的地形和旧河流。** 实服回归只使用项目既有的无人测试存档，检查后正常保存关闭。

本轮针对两个具体原因：旧山脊从连续噪声等值线抬高，在漩涡拉伸后出现成排条带；对称河宽、统一圆帽/圆滑汇口使河流像画笔描线。去除圆帽并不等于实现了真实曲流，因此仍保留下面的限制和验收门槛。

## 实现范围

- `NaturalRelief`：有限长度、多峰、可分叉的山脊与不同宽度的两侧山坡，叠加世界坐标丘陵和有限扰动。大方向仍受漩涡影响，但不再沿一组连续等值线抬山。分支数量、长度、方向独立变化；不是物理侵蚀模拟。实例持有有界线程局部缓存，不使用跨存档的静态地形缓存。
- `BaseTerrain.naturalPrototype`：显式离线入口。只替换干旱股/湿润股的候选起伏；中心保护区、海洋、下界股、陆地遮罩和径向基线不变。正式 `TerrainProfile` 继续调用原有构造器。
- `DrainageMesh` / `DrainageGraph.buildNatural`：增大有界采样抖动，改用非规则 Delaunay 邻接，减少规则网格的横竖/对角方向偏好。地形决定排水图；实际群系温度、降水和降水开关继续决定有效来水。保留 Priority-Flood、汇水累计、河级与有限域终点诊断。
- `RiverBanks`：沿排水图按流量展宽，两岸独立收缩/外扩；以渐窄源头替代圆帽，汇口使用有棱角的连接多边形，局部山坡参与岸带宽度。邻近非汇流河段限制展宽，降低意外连河风险。**这里只产生二维岸线提案，没有侵蚀 H0，也没有生成水方块。**
- `verifyNaturalHydrology`：从同一组实际算法数据输出完整河网、地形及近景，不用概念图替代算法结果；保留 V1 的独立任务和对照数据。

三角网的方向/内圆判定使用 double 快速路径和近退化情况下的 `BigDecimal` 回退。数值风险的依据是 [Shewchuk 的几何判定说明](https://www.cs.cmu.edu/~quake/robust.html)；本项目没有复制其 C 代码，也不声称这里实现了其自适应展开算法。当前实现是有顶点数上限的离线求解器，不应直接放入区块热路径。

开发中坡度测试捕获了一个实际接缝：山脊端部使用左右坡宽的硬切换。现改为连续过渡，避免用渲染平滑掩盖高度跳变。

## 本轮观察与量化口径

种子 42 的代表性结果：

| 指标 | 湿润温带/丛林 | 远端山地 |
| --- | ---: | ---: |
| 地形主方向集中度：旧 → 新 | 0.7807 → 0.0580 | 0.8464 → 0.1012 |
| 河网八方向偏好：规则网 → 非规则网 | 0.5819 → 0.0590 | 0.6074 → 0.0755 |
| 高于径向基线 30 格的采样占比：旧 → 新 | 20.45% → 8.14% | 18.50% → 9.03% |
| 新两岸平均相对宽度差 | 6.01% | 5.82% |
| 分析积水超过 4 格的提案片段数 | 266 | 391 |

地形方向集中度来自坡向协方差；八方向偏好来自河段方向的第八谐波，比较时使用**相同的新 H0**，隔离网格变化。数值降低说明特定规则性减弱，不等于“自然程度提高百分之多少”，也不代替目视验收。片段数不是独立湖泊或河流数量。

高地覆盖率下降是真实的形态变化，不能隐藏：有限山体不再像旧长条山脊一样占据大片区域。保留了独立峰顶和较宽山麓，但山地区域仍可能过于疏松，需要后续样品反馈继续调整。没有依据排水势填平山峰，也没有把地形整体铺成平面。

## 验证与未通过项

V2 覆盖种子 `42 / 0 / -739221`，每种三个完整域：

- 复用 V1 的拓扑无环、汇水/水量收支、水位单调和不穿虚空检查。
- 检查非汇流河道中心线不相交、单个水面提案多边形不自交、正宽度及两岸非镜像；明确这不等于所有展宽后多边形之间都不会意外重叠。
- 重建结果一致，基础地形并行/逆序/缓存淘汰一致；降低降水不改变排水拓扑，也不能增加流量。
- 中心与特殊陆地股保持原样；同坐标网格上的一格高度差样本最大为 1～2 格。这个数是有限采样结果，不是所有坐标的严格数学上界。
- 每端 V2 独立计数 1,447,784 次断言，另复用 V1 图检查；Java 17/21 的九组图/岸线指纹一致。

**`INTEGRATION_GATE=FAIL` 保留。** 当前仍然存在：

1. 独立父域没有全局共享汇水边界与水位/水量契约；没有声称解决 V1 的跨父域接缝。
2. 河线仍沿粗三角网折线，近景容易像折线路网；需要在原有连通走廊内做谷地约束的细化，兼顾急弯、缓弯和直段，不能仅给所有拐点统一倒圆。
3. Priority-Flood 的深积水只是分析诊断，湖盆收支、溢口和开山限制仍未验收；不将这些积水直接填进世界。
4. 岸线的 `supported` 只检查边界采样落在合法陆地上，不证明内部无孔、不证明方块水封闭；展宽后的全网相交/不应连通区域还需要专门验收。
5. 河床纵剖面、实际内外弯断面、方块水 tick/冻结和地物/结构水岸保护尚未接入。未进行新算法的游戏内视觉验收。

下一步先解决全局排水契约和深洼去向，再在确定的连通走廊内消除粗折线、恢复合理的山体密度。形态确认与技术门槛都通过后，才能进入河床/方块水实现。

## 复现

先按 README 从两个无人测试服导出实际注册表 `climate.tsv`，关闭服务器后运行：

```powershell
.\gradlew.bat :1.20.1-forge:build :1.21.1-neoforge:build :1.20.1-forge:verifyHydrologyPrototype :1.21.1-neoforge:verifyHydrologyPrototype :1.20.1-forge:verifyNaturalHydrology :1.21.1-neoforge:verifyNaturalHydrology --no-build-cache --console=plain
```

局部测试退出成功与 `INTEGRATION_GATE=FAIL` 并不矛盾：前者证明已覆盖的局部性质，后者阻止尚未达标的离线实验被当作可用世界生成发布。求解耗时含地形统计、两套邻接对照和岸线构造，以报告为准；不是正式区块吞吐指标。
