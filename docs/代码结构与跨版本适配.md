# 代码结构与跨版本适配

Java 包根目录为 `com.tonywww.deeprealm4th`，模组 ID 为 `deeprealm_4th`。Forge 1.20.1 与 NeoForge 1.21.1 共用 `src/main/java`；Stonecutter 根据 `//? if` 指令生成目标版本源码。

## 功能分包

| 包 | 职责 |
| --- | --- |
| `astral`、`astral.container` | 填充物定义、固定规则、容器布局与运行时 |
| `astral.node`、`astral.score` | 逐格节点、读取依赖、玩家快照、大数分数与属性结算 |
| `astral.data`、`astral.process` | 宝石数据 schema、物品数据传递、工艺谓词与变换 |
| `astral.content`、`astral.tooltip` | 内置内容目录、规则注册、动态展示与提示 |
| `item`、`block`、`blockentity` | 物品、母岩与晶体、皮革垫及持久输入 |
| `menu`、`screen`、`client.render` | 服务端交互、界面与框架模型 |
| `worldgen` 下的 `biome/codec/hydrology/layout/surface/terrain` | 群系池、水系、螺旋布局、材质与地形 |
| `travel`、`loot` | 虚空旅行与深境四层宝箱晶石 |
| `integration.jei`、`integration.kubejs` | 可选集成 |
| `platform` | 加载器注册、事件、配置、配方序列化、物品存储和 API 签名适配 |
| `mixin` | 原生写入保护、物品栏入口与物品光效钩子 |

## 平台适配边界

`platform.ModEntrypoint` 是加载器发现的 `@Mod` 类，`platform.PlatformBootstrap` 注册目标版本内容。根类 `DeepRealmTheForth` 提供稳定模组 ID。

玩法规则放在功能包，跨版本差异封装为平台入口供业务调用。例如：

- `astral.content.AstralItemCatalog` 定义内置物品及提示，`platform.registry.AstralItemRegistration` 对接加载器注册表。
- `block.ForgingPadBlock`、`blockentity.ForgingPadBlockEntity` 保存输入，`menu.ForgingPadMenu` 处理锤击与结算；菜单打开与存储签名由平台层适配。
- `astral.node.AstralNodeEngine` 计算逐格分数，`platform.curios.CurioAttributePlatform` 将属性结果交给两版 Curios。
- `loot.FourthLayerGemLoot` 决定维度筛选与候选池，平台战利品修饰器接入各加载器。
- `travel.MimeticVoidTravel` 实现旅行条件，平台事件适配器传入玩家 tick。

新增内容先放在对应功能包；遇到加载器或 Minecraft 版本 API 差异时，再提供平台适配方法。

## 开发入口

- 容器继承 `item.AstralContainerItem`，布局使用 `astral.container.ContainerLayout`。
- 固定规则从 `AstralFillers`、`FillerDefinition`、`ScoreRules` 接入。
- 动态规则从 `astral.node.FillerNode`、`ReadPlan`、`FillerFilter` 接入。
- 宝石数据和分数使用 `astral.data.GemPayload`、`astral.score.AstralNumber`。
- 内置两类工艺配方由 [GenerateAstralProcessRecipes.java](../scripts/GenerateAstralProcessRecipes.java) 生成，构建脚本自动处理 `recipe/recipes` 等资源路径差异。

可复制的 Java / KubeJS 示例见[快速指南](星界饰品-开发者快速指南.md)，复杂节点与数据加工见 [API 指南](星界宝石系统-API扩展开发者指南.md)。
