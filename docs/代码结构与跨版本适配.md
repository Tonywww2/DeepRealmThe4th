# 代码结构与跨版本适配

Java 包根目录是 `com.tonywww.deeprealm4th`，模组 ID 保持 `deeprealm_4th`。Forge 1.20.1 与 NeoForge 1.21.1 共用 `src/main/java`；Stonecutter 根据 `//? if` 指令生成各版本源码。

| 包 | 职责 |
| --- | --- |
| `astral`、`astral.container`、`astral.score`、`astral.process`、`astral.tooltip`、`astral.content` | 填充物规则、容器、分数、工艺和提示 |
| `item`、`block`、`menu`、`screen`、`client.render` | 物品方块与界面行为 |
| `worldgen` 下的 `biome`、`codec`、`hydrology`、`layout`、`surface`、`terrain` | 深境四层世界生成 |
| `command`、`travel`、`loot` | 指令、虚空旅行和宝箱晶石规则 |
| `integration.jei`、`integration.kubejs` | 可选集成的共用逻辑 |
| `platform` 下的 `registry`、`event`、`recipe`、`data`、`item`、`screen` 等 | 加载器注册、事件签名、配方序列化、物品数据格式和方法签名的双版本适配 |

`platform.ModEntrypoint` 是加载器发现的 `@Mod` 类，`platform.PlatformBootstrap` 注册各版本内容。根目录的 `DeepRealmTheForth` 只保存稳定的模组 ID。业务规则在功能包中实现，事件适配器将玩家、物品栏或配方输入交给它们，再把结果写回对应版本的 API。例如：

内置物品及其提示由 `astral.content.AstralItemCatalog` 定义；`platform.registry.AstralItemRegistration` 只把这些定义交给对应加载器的物品注册表。

- `block.ForgingPadBlock` 与 `blockentity.ForgingPadBlockEntity` 管理铁砧上的持久输入；`menu.ForgingPadMenu` 完成服务端锤击与经验结算，跨版本菜单打开及 NBT 方法由 `platform` 适配。
- `platform.curios.CurioAttributePlatform` 将 `astral.score.AstralCurioAttributes` 的结果转换为两版 Curios 属性修饰符，并适配物品数据存储。
- `platform.loot.FourthLayerGemLootModifier` 调用 `loot.FourthLayerGemLoot` 执行宝箱抽取。
- `platform.event.MimeticVoidTravelEvents` 将玩家 tick 交给 `travel.MimeticVoidTravel`。

新增玩法时，先把规则放在相应功能包；仅在调用加载器或版本不同的 Minecraft API 时新增 `platform` 入口。公开的填充物扩展入口仍是 `AstralFillers`、`FillerDefinition`、`ScoreRules`，自定义容器继承 `item.AstralContainerItem`。示例见[星界饰品开发者快速指南](星界饰品-开发者快速指南.md)。
