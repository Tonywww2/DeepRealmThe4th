# 河流长度调整与验证

日期：2026-09-28。目标是让真正生成出来、连通到终端湖的河流主干，通常达到调整前约三倍长度；不通过把河道坐标机械拉伸来实现。

## 改动

- `GlobalDrainage` 仍只在同一陆地支系中选择严格下降、经过陆地走廊检查的相邻站点；下游选择由“最陡下降”改为“最缓下降”，让水流沿缓坡走得更远。势能秩仍严格递减，因此不会生成环。
- 可见河源的汇水阈值由 12,000 降至 8,000；河宽和河床深度仍按原来的 12,000 流量标尺计算，避免把新上游小溪放大成宽河。局部径流和蒸发仍来自群系气候快照。
- `RiverLengthVerification` 以实际通过河道、切深和终端湖检查的模型为样本，沿已生成的河道折线计算每个流域最长的河源至河口路径，而非仅统计理论排水图。

## 固定样本结果

相同 seed=42、三个 2,048×2,048 区域的稀疏固定站点，共涉及调整前 49 个、调整后 48 个独立流域。站点与流域集合因路径重排略有变化，所以这是分布对比，不是逐条河一一配对。

| 指标 | 调整前 | 调整后 | 变化 |
| --- | ---: | ---: | ---: |
| 通过检查的河网 | 24 | 23 | 少 1 个 |
| 主干平均长度 | 310.7 格 | 914.8 格 | 2.94 倍 |
| 主干中位长度 | 321.1 格 | 867.0 格 | 2.70 倍 |
| 主干第 75 百分位 | 433.1 格 | 1,333.2 格 | 3.08 倍 |
| 全样本河道总长度 | 13,805 格 | 33,702 格 | 2.44 倍 |
| 已接受河段数 | 185 | 434 | 2.35 倍 |

新旧结果可复现：使用 `RiverLengthVerification` 分别针对 `build/river-length-baseline`（改动前字节码）及当前世界生成源码运行，并传入 `run/forge-server/biome-compat-v5/climate.tsv`。诊断类打印每条河的主干和汇总。

完整水系检查在改动后的结果：`ACCEPTED=23`、`DRY=16`、`LAKE_CAPACITY=9`；河段相交、湖泊重叠、河水连通、切深上限、直接侧漏、并发/缓存边界一致性均通过。固定区域河水列 9,452，侧漏 0，最大切深 15 格。地形指纹已更新到本次河道形态。

## 性能与边界

河段增加会提高水系密集处的成本。同一固定四区域纯地形模型基准中，密集河流区的热态串行中位数约从 113.5 ms 增至 131.5 ms；四线程单次从 126.3 ms 到 127.9 ms，差距接近测量波动。原始计时分别见 `build/reports/river-length-baseline-benchmark/timing.txt` 和 `build/reports/worldgen-performance/forge/river-long-8000-20260928/timing.txt`。这不是 FULL 区块、TPS 或客户端帧率测量，不能据此保证整服成本不变。

三倍是固定样本的平均主干目标，不代表每一条河都恰好三倍；少数流域仍较短。新生成区块使用新形态，已经生成的旧区块不会自动重写，存档边界可能出现河道衔接差异。
