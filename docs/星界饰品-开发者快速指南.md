# 星界饰品开发者快速指南

适用版本：Forge 1.20.1、NeoForge 1.21.1。KubeJS 为可选依赖。以下 `addon:*` 和 `kubejs:*` 均为技术示例 ID，数值也只是示例平衡值；把它们放入你的附属模组或整合包时，可自行命名和调整。

## 物品类型 tag

本模组为内置物品提供如下 item tag。`astral/fillers` 汇总 `astral/gems` 与 `astral/medals`；容器另列，不算填充物。tag 用来识别物品类别，**不决定** `STACKABLE`、`UNIQUE_WORN` 或 `UNIQUE_EFFECT` 等结算方式。

| Tag ID 前缀 `deeprealm_4th:astral/` | 含义 |
| --- | --- |
| `containers` | 星界躯体类容器 |
| `fillers` | 全部填充物 |
| `gems`、`medals` | 晶石、徽章／勋章 |
| `base_gems`、`combination_gems`、`conversion_gems` | 基础、组合、转换晶石 |
| `tradeoff_gems`、`percentage_gems`、`player_condition_gems` | 取舍、比例、玩家条件晶石 |

检测物品类型时使用完整 tag ID，例如 `deeprealm_4th:astral/medals`；它已涵盖本模组的内置勋章，其他物品只有实际带有该 tag 才会被计数。附属物品还要有自己的物品注册、语言键、模型与贴图。自定义容器必须继承 `AstralContainerItem`，并符合 Curios `base_container` 槽位的物品匹配规则。

## KubeJS：四个完整功能示例

安装与游戏版本匹配的 KubeJS。在 `kubejs/startup_scripts/astral_quickstart.js` 中写入：

```js
StartupEvents.registry('item', event => {
  // 5×5，X 为开放格，共 9 格；createCustom 产生真正的 AstralContainerItem。
  event.createCustom('kubejs:cross_body', () => AstralContainers.create(
    5, 5, '..X..', '..X..', 'XXXXX', '..X..', '..X..'))
  event.create('kubejs:sixfold_medal')
  event.create('kubejs:level_strength')
  event.create('kubejs:linked_magic')
})

// 六项最终分数各取非负部分，相加后每 1 分给予 +0.1 最大生命值。
AstralFillers.register('kubejs:sixfold_medal',
  FillerDefinition.builder()
    .activation(FillerActivation.UNIQUE_EFFECT)
    .medal(AstralRules.attributePerAllScores('minecraft:generic.max_health', 0.1))
    .build())

// 30 级不触发；31 级及以上总计力量 +6。
AstralFillers.register('kubejs:level_strength',
  FillerDefinition.builder()
    .activation(FillerActivation.STACKABLE)
    .base(ScoreType.STRENGTH, 2)
    .bonus(AstralRules.whenExperienceLevelAbove(30, ScoreType.STRENGTH, 4))
    .build())

// 上下左右至少两个开放且有效的相邻格放有“徽章”tag 物品时，
// 按本轮基础魔力总分的 10% 额外获得魔力；不消耗来源分数。
AstralFillers.register('kubejs:linked_magic',
  FillerDefinition.builder()
    .activation(FillerActivation.UNIQUE_EFFECT)
    .base(ScoreType.MAGIC, 3)
    .bonus(AstralRules.percentWhenAdjacentTagAtLeast(
      'deeprealm_4th:astral/medals', 2, ScoreType.MAGIC, ScoreType.MAGIC, 0.10))
    .build())
```

自定义容器还需要物品模型。例如 `kubejs/assets/kubejs/models/item/cross_body.json` 可暂时引用本模组贴图：

```json
{"parent":"minecraft:item/generated","textures":{"layer0":"deeprealm_4th:item/base_container"}}
```

其余三件示例物品也应配模型、贴图和语言键。修改 `startup_scripts` 后必须重启游戏。普通 KubeJS `event.create(...)` 生成的物品可以作填充物，但不能直接作容器；容器示例使用 `createCustom` 返回了 `AstralContainerItem`。

## Java：同样四种能力

把下面的类放入附属源码，并在自己的物品延迟注册器中调用 `ITEMS.register("cross_body", CrossBody::new)`：

```java
import com.tonywww.deeprealm4th.astral.*;
import com.tonywww.deeprealm4th.astral.container.ContainerLayout;
import com.tonywww.deeprealm4th.item.AstralContainerItem;
import com.tonywww.deeprealm4th.item.AstralFillerItem;
import com.tonywww.deeprealm4th.astral.score.AstralAttributeIds;
import java.util.List;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.ItemStack;

public final class CrossBody extends AstralContainerItem {
    private static final ContainerLayout CROSS = ContainerLayout.parse(5, 5, List.of(
            "..X..", "..X..", "XXXXX", "..X..", "..X.."));

    public CrossBody() {
        super(new Item.Properties());
    }

    @Override
    public ContainerLayout layout(ItemStack stack) {
        return CROSS;
    }
}
```

其余三件物品也要注册到附属的物品延迟注册器。要复用自动提示，可创建 `AstralFillerItem` 并传入自己的翻译键，例如：

```java
ITEMS.register("sixfold_medal", () -> new AstralFillerItem(
        new Item.Properties().stacksTo(1), "tooltip.addon.sixfold_medal.effect"));
ITEMS.register("level_strength", () -> new AstralFillerItem(
        new Item.Properties().stacksTo(1), "tooltip.addon.level_strength.effect"));
ITEMS.register("linked_magic", () -> new AstralFillerItem(
        new Item.Properties().stacksTo(1), "tooltip.addon.linked_magic.effect"));
```

`ITEMS` 是你在相应加载器中创建并接入事件总线的物品注册器；上述翻译键要写入附属语言文件。在附属初始化时，为这些物品 ID 各调用一次 `AstralFillers.register`：

```java
AstralFillers.register("addon:sixfold_medal", FillerDefinition.builder()
        .activation(FillerActivation.UNIQUE_EFFECT)
        .medal(ScoreRules.attributePerAllScores(AstralAttributeIds.MAX_HEALTH, 0.1))
        .build());

AstralFillers.register("addon:level_strength", FillerDefinition.builder()
        .activation(FillerActivation.STACKABLE)
        .base(ScoreType.STRENGTH, 2)
        .bonus(ScoreRules.whenExperienceLevelAbove(30, ScoreType.STRENGTH, 4))
        .build());

AstralFillers.register("addon:linked_magic", FillerDefinition.builder()
        .activation(FillerActivation.UNIQUE_EFFECT)
        .base(ScoreType.MAGIC, 3)
        .bonus(ScoreRules.percentWhenAdjacentTagAtLeast(
                "deeprealm_4th:astral/medals", 2,
                ScoreType.MAGIC, ScoreType.MAGIC, 0.10))
        .build());
```

需要自定义 tag 条件时，Java 回调也可以直接调用 `context.countAdjacentTag("deeprealm_4th:astral/medals")`；KubeJS 回调中的 `context` 提供相同方法。它返回上下左右四个有效相邻格中匹配该 tag 的物品数量。

六分数徽章示例把六项分数合并为一种属性；需要分别映射到不同属性时，可给同一 `FillerDefinition` 连续添加六条 `ScoreRules.attributePerScore(...)`，KubeJS 则使用 `AstralRules.attributePerScore(...)`。

## 自定义加分：读取其他模组的 API

以下示例直接调用 Curios API：玩家在 `ring` 槽位装备至少两件物品时，额外获得感应 `+3`。这要求整合包实际配置了 `ring` 槽位；可把 `ring` 换成目标模组提供的 Curios 槽位标识。示例填充物本身可叠加，且只有装备容器时才结算。

KubeJS：在 `startup_scripts` 中注册物品和规则。`.bonus(...)` 接受自定义回调；参数依次是填充物上下文、当前阶段分数、加分输出。

```js
const CuriosApi = Java.loadClass('top.theillusivec4.curios.api.CuriosApi')

StartupEvents.registry('item', event => {
  event.create('kubejs:ring_resonance')
})

AstralFillers.register('kubejs:ring_resonance',
  FillerDefinition.builder()
    .activation(FillerActivation.STACKABLE)
    .bonus((context, phaseScores, output) => {
      const hasTwoRings = CuriosApi.getCuriosInventory(context.player())
        .map(inventory => inventory.findCurios('ring').size() >= 2)
        .orElse(false)
      if (hasTwoRings) output.add(ScoreType.PERCEPTION, 3)
    })
    .build())
```

示例物品还需要模型、贴图和语言键。

Java：注册 `addon:ring_resonance` 物品后，在附属初始化时注册同一规则。`ScoreRules.when` 接受 `FillerContext` 谓词，可直接调用依赖模组的 API。

```java
import top.theillusivec4.curios.api.CuriosApi;

AstralFillers.register("addon:ring_resonance", FillerDefinition.builder()
        .activation(FillerActivation.STACKABLE)
        .bonus(ScoreRules.when(context -> CuriosApi.getCuriosInventory(context.player())
                        .map(inventory -> inventory.findCurios("ring").size() >= 2)
                        .orElse(false),
                ScoreType.PERCEPTION, 3))
        .build());
```

两版 Curios 的 `getCuriosInventory` 返回类型不同，但这里使用的 `map(...).orElse(false)` 在两版均可用。自定义判断保持只读；不要在加分回调内修改玩家、容器或其他模组的数据。

## 结算要点

- tag 相邻计数仅看上下左右四格，且只计开放、有效的填充物；关闭格、冲突失效物品和唯一效果的后续副本不计。两个相邻徽章分别占两格；若两件是同 ID 的 `UNIQUE_EFFECT` 勋章，后续副本不会计入。
- 比例加分读取**基础分阶段结束时**的魔力总分，不读取其他同阶段加分。仅有示例晶石的基础魔力 `3` 时，满足相邻条件得到 `+0.3`，最终魔力 `3.3`。
- 所有规则由同一逐格节点引擎执行；上述 `.base/bonus/medal` 是固定规则便利接口。勋章在节点汇总之后读取最终分数，并由佩戴中的容器通过 Curios 应用属性。依赖读取和大数节点见 [API 指南](星界宝石系统-API扩展开发者指南.md)。
- `deeprealm_4th:astral/medals` 由 item tag 判定，与物品名是否包含 `medal` 无关。
