# 地形比例与旋转调整

## 改动

按本轮要求，将四组陆地/虚空对保持为每对 90°，在每对内部采用 3:1 分配：

| 项目 | 初版 | 本轮 |
| --- | --- | --- |
| 每个非虚空股 | 45°，1/8 | 67.5°，3/16（18.75%） |
| 每个虚空股 | 45°，1/8 | 22.5°，1/16（6.25%） |
| 四股非虚空总占比 | 50% | 75% |
| 四股虚空总占比 | 50% | 25% |
| 旋转强度 twist | 0.72 | 1.44 |

面积指以中心为圆心的圆环内的理论分区。半径 16 的中央空洞和陆地边缘 1.5 格留白继续保留，因此实际实体地形面积略低于理论 75%。股号、四种生态、向内顺时针方向和径向高度曲线未改变。

旋转强度翻倍表示同一径向区间的绕转角度翻倍，而不是把整个维度刚性转向。相位仍为 `theta + twist * ln(r / referenceRadius) - rotation`。

## 实现

`SpiralLayout` 不再把圆周等分为八份，而是先取四个陆地/虚空对，再按 `land_fraction` 划分两种宽度。边缘距离和 `armCenter` 同步改用各自实际宽度，所以岸堤、厚度、装饰避边、群系选择及传送目标使用同一套布局。

当前维度 JSON、Java 默认值和 Codec 的默认值一致：

```json
{
  "twist": 1.44,
  "land_fraction": 0.75
}
```

路径为 `src/main/resources/data/deep_realm_the_forth/dimension/fourth_layer.json` 的 `generator.biome_source.parameters`。`land_fraction` 支持 0.1～0.9；本轮默认 0.75。

新服务端测试使用 `run/<loader>-server/verification-world-layout-v2`，种子 42，不带上轮故意修改群系池的测试数据包。

- Forge 实际 24 列比对通过：`fingerprint=344cbe64705c4f9e possibleBiomes=27 landFraction=0.75 twist=1.44`。
- NeoForge 实际 24 列比对通过，指纹、群系数量和参数与 Forge 一致。
- 两版均通过持续 tick 后的 4 处流体样本、60 项非源流动状态检查；测试加载票已撤销，服务器已正常保存关闭。
- 已打开两个构建 JAR，确认各自打包的维度 JSON 确实包含 `land_fraction=0.75`、`twist=1.44`。

## 查看效果与旧存档限制

请用更新后的对应版本 JAR **新建世界**，然后执行 `/fourthlayer enter`。最新预览为 [overview.png](../build/reports/terrain/overview.png)，这是实际算法采样图，不是游戏截图。

旧世界测试确认：游戏会重新读取数据包里的维度配置，但已存在的区块不重生成。直接加载上轮测试世界时，新模型与旧区块不再匹配，不能靠新增参数的解码默认值保证旧地形连贯。因此本轮不迁移或删除已有世界；新旧地形接缝属于升级限制，不代表新世界生成失败。

两个更新后的 JAR 仍在对应 `versions/<节点>/build/libs/` 下，文件版本保持 0.1.0；之前验证文档里的初版文件大小和 SHA-256 不适用于本次重新构建。
