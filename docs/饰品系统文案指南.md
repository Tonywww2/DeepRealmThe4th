# 饰品系统文案指南（草案）

本指南用于星界躯体、填充物、职业勋章、容器界面、指南书及相关进度文本。它整理自 Dust and Ash 的 `COPYWRITING_GUIDE.md`，保留“物件 → 效用 → 条件或代价 → 已确认来历 → 余韵”的写法，并针对本项目的宝石、星体与星座主题调整。文案示例是写作样稿，不代表物品配方、视觉资源或交互细节已经实现。

## 1. 已确认的事实与边界

- 核心饰品名称为“星界躯体”，物品 ID 为 `base_container`。它自身附着一个可放置填充物的容器；从物品栏右键它，或直接使用它，可以打开容器。
- 容器可用格子由配置中的 12×9 矩阵决定，`X` 表示开启的格子。文案不写死可用格数。
- 六项基础分数是力量、敏捷、智力、体质、感应、魔力。**分数本身不提供属性加成。**
- 填充物可以直接增加分数，也可以在条件满足时增加分数、依据一种分数增加另一种分数，或将一种分数转换为另一种分数。每件物品的具体条件与结算方式以实际定义为准。
- 力量晶石每件提供 +1 力量分数，可叠加。职业勋章可以依据分数产生属性加成，最终结算到容器饰品上。已给出的样例是“战士勋章”：按最终力量 `s` 使最终攻击力提升 `ln(1 + max(0,s)/15) × 100%`，属于唯一效果。
- 宝石、星体与星座是系统的基础设定：宝石承载星体力量，星座决定组合规则。物品、规则、界面和故事文本应遵循这个关系。具体宝石、星体、星座与六分数或职业的对应尚待确认。

制造者、组织、年代、起源、宗教、星象法则，以及饰品与现有维度的剧情关系，尚无已确认设定。不得用“古老星术”“失落文明”等套语补足。新填充物的具体效果与生效类型应依据注册定义写入；未确认的获取方式、宝石与星体对应及星座组合效果不得写成事实。

## 2. 命名与语气

- 中文使用自然、克制的现代书面语。让宝石的可观察性质和星象的几何形态承担意象，少用“神秘、无尽、至高、史诗”等空泛评价。
- 物品名简短且可区分。容器类可采用“星界躯体”这样的核心称呼；其他名字可从光泽、切面、轨道、星图、连线等具体形态取材，但不因名字暗示未经证实的机制。
- 六项分数固定称为“力量分数”等；界面空间有限时可用“力量”等短名。叙述中区分“分数”与实际属性，例如“力量分数”不等于“攻击力”。
- “填充物”“职业勋章”是当前设计用语。玩家可见的最终分类名尚待确认，翻译键和指南书在确认前保持同一用语。
- 尽量以物件、佩戴者或容器为主语。操作指南可以直接用祈使句；物品描述以陈述句为主。
- 不把内部类名、事件名、NBT、注册表结构或 `otheronme` 写进普通玩家文案。配置和扩展文档可以精确写这些术语。
- 中文使用全角标点；技术 ID、按键名和数值格式保留其原样。语言文件中不嵌入 `§` 颜色码，由界面统一处理。

## 3. 文本层级

| 场景 | 内容 | 建议长度 |
| --- | --- | --- |
| 物品名 | 准确识别物品 | 尽量简短 |
| 默认提示 | 一句话说明身份与核心用途；有效果时保留影响对象 | 通常 16～30 个汉字 |
| 详细提示 | 逐行说明效果、条件、限制与结算对象 | 核心物品通常 2～5 行 |
| 容器界面 | 格子、分数和操作状态；数据与名称必须优先可读 | 按布局决定 |
| 指南书 | 先讲操作步骤，再讲分数和勋章的关系 | 按任务拆段 |
| 进度描述 | 刚完成的事实及其直接意义 | 通常一句话 |

参考指南中的 Alt、Shift 分层可作为界面方案，但当前项目尚未确认采用这些按键。若实现分层提示，详细内容应替换简述；精确数值应放在效果句内，使单独阅读任一层都能理解规则。条件、消耗、上限和例外不能藏在只有少数玩家会打开的层级里。动态配置、脚本或填充物会改变数值时，显示实际结算值或参数化文本，不写死默认值。

## 4. 分类写法与样稿

以下句子只使用已确认的机制；其中样稿仍须根据最终交互和数值呈现校对。

### 星界躯体

顺序：物件身份 → 打开方式 → 填充物与分数的关系。示例：

> 星界躯体：附有可容纳填充物的空间。
>
> 在物品栏中右键，或直接使用，可打开容器。
>
> 容器中的填充物参与分数结算。

界面中应明确区分“可用格子”和关闭格子，不用叙事词替代状态。若某项操作需要饰品被佩戴、手持，或具有别的先决条件，应等交互规则确认后补上。

### 普通填充物

顺序：可辨的形态或材质 → 增减哪项分数 → 触发条件。力量晶石可直接写“+1 力量分数”；其他尚未确定名称、数值或条件的宝石只使用句式模板，不造出正式物品：

> 放入容器后，增加〔数值〕点〔分数名称〕分数。
>
> 满足〔可验证条件〕时，额外获得〔数值〕点〔分数名称〕分数。

“增加”“转换”“依据……获得”不可混用。转换必须同时说清来源分数、目标分数与数量；按比例增加必须说明计量单位和舍入规则。若规则尚未确定，不发布含糊的“强化星力”替代机制说明。

相邻填充物规则应写清目标物品、方向和触发次数，例如“上下左右相邻的开放格中有〔填充物 A〕时，增加〔数值〕点〔分数〕分数”。如果多个 A 只触发一次，要写“有至少一个”或“只触发一次”；斜对角与关闭格不计入相邻关系。

### 职业勋章

顺序：勋章身份 → 所读取的分数 → 产生的属性 → 生效对象或限制。战士勋章样稿：

> 战士勋章：依据力量分数提高攻击力。
>
> 力量分数最低按 0 分计算；最终攻击力提升 `ln(1 + 力量分数/15) × 100%`。力量分数为 15 时约提升 69.3%；加成结算到星界躯体上。

若界面已经以原版属性栏显示精确加成，提示可以解释换算规则，避免重复列出同一个结算结果。有关佩戴要求、叠放、多个勋章和小数精度的句子，须等规则确定。

## 5. 宝石与星象意象

三个元素承担不同的表达功能，但不预设它们在游戏机制中一一绑定：

| 元素 | 可用的具体词汇 | 写作时需要的证据 |
| --- | --- | --- |
| 宝石 | 晶面、棱线、内含物、透光、刻痕 | 贴图、模型或已确认的材质设定 |
| 星体 | 光点、轨道、遮掩、明暗、方位 | 实际视觉表现或明确设定 |
| 星座 | 连线、图形、排列、缺口、重合 | UI、图案或明确设定 |

可以让物品的形态呼应这些意象，例如描述“晶面上的连线”，前提是资源里确有相应图案。文案应准确表达宝石承载星体力量、星座决定组合规则；不能据此擅自宣称某宝石对应力量或某星座属于战士。正式命名与效果文本仍需明确宝石、星体和星座名录及其具体关系。

## 6. 操作文本与本地化

- 容器按钮、槽位、错误提示与配置说明以可执行信息为主。例如“该格未开启”比“此星位仍在沉睡”更适合即时反馈。
- 分数面板应提示“分数本身不提供属性加成”，并把职业勋章等实际转换来源单独标明。不要将某项分数显示为原版属性的同义词。
- 加成文案必须写明数值单位、正负号和换算方向。对战士勋章明确写“最终攻击力百分比”和力量 15 时约 +69.3% 的例子，避免把对数值误读成固定攻击力或把 0.693 写成 0.693%。
- 英文与中文表达同一机制和条件；翻译占位符的数量、顺序与类型保持一致。资源 ID 不翻译，玩家可见名称要翻译。
- 配置文档可写 `12×9`、`X` 与示意矩阵；玩家界面只显示玩家当下需要的结果。若格局会因配置或饰品类型变化，文案不承诺固定可用格数。

## 7. 审校清单

- 是否能从文案明确判断这是容器、填充物，还是职业勋章？
- 是否准确区分六项分数与原版或其他模组属性？
- 条件分数、分数换算和属性加成的来源、目标、单位是否清楚？
- 数值是否与当前实现及配置一致，且没有隐藏必要条件？
- 宝石、星体和星座的描述是否遵循已确认的基础设定，未确定的关系是否明确保留？
- 是否出现未经确认的人物、历史、因果关系或与深境四层的关联？
- GUI 文本能否帮助玩家完成操作，错误信息能否指出下一步？
- 中英文是否保持同一事实，所有翻译占位符是否一致？
