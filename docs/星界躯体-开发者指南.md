# 星界躯体：Java 与 KubeJS 扩展指南

本指南对应当前源码。目标版本是 Forge 1.20.1 和 NeoForge 1.21.1；Curios 是必需依赖，KubeJS 是可选依赖。核心公开类位于 `com.tony.deeprealmtheforth.astral`。

## 注册一件填充物

填充物按物品 ID 关联定义，因此既能使用附属模组新物品，也能使用已有物品。注册只做一次；物品必须真实存在，且不要注册为可装入自身的容器。

```java
AstralFillers.register("addon:orbit_gem", FillerDefinition.builder()
    .activation(FillerActivation.STACKABLE)
    .base(ScoreType.STRENGTH, 2)
    .bonus(ScoreRules.adjacent("addon:anchor_gem", ScoreType.STRENGTH, 3))
    .bonus((context, phaseScores, output) -> {
        if (context.player().getHealth() < 10) {
            output.add(ScoreType.CONSTITUTION, 1);
        }
    })
    .bonus((context, phaseScores, output) ->
        output.add(ScoreType.AGILITY, phaseScores.get(ScoreType.STRENGTH) * 0.5))
    .build());
```

此段是 **API 写法示例**，`addon:*` 物品与数值不是项目正式设定。`ScoreRules.adjacent` 只检查上下左右开放格；至少一个指定物品相邻时加分一次。`FillerContext` 还提供 `x()`、`y()`、`itemAt(x,y)` 和 `count(itemId)`，便于附属写自己的组合条件。关闭格内容虽然持久保存，却不会参与结算或邻接查询。

每件填充物可选择 `FillerActivation.UNIQUE_WORN`（同 ID 只允许放 1 件）、`STACKABLE`（多件各自结算）或 `UNIQUE_EFFECT`（多件可放但同 ID 只结算第一个开放格）。默认是 `STACKABLE`。`.suppressedBy("addon:anchor_gem")` 是有向冲突：指定物品出现在任一开放格时，本件保留在格子里但暂不结算，移除对方后自动恢复。冲突只影响结算，不改变物品存储；界面悬停会提示冲突或重复造成的暂不生效。

结算顺序固定为基础分、附加分、转换、勋章。附加分规则读取同一份阶段开始时的 `ScoreSheet`；转换按格子从左到右、从上到下使用剩余分数，来源不足时按可用量缩小该条转换。Java 回调可读取玩家状态，但应避免修改玩家、容器或传入的物品栈；回调抛异常时该条规则本轮失效并进入诊断结果。六分数自身不会改变任何 Minecraft 属性。

战士勋章作为内置示例注册为 `deeprealm_4th:warrior_medal`。先将最终力量分数 `s` 按最低 0 分处理，再使最终攻击力提升 `ln(1 + max(0,s)/15) × 100%`。`s=15` 时约为 +69.3%；任何负力量均按 0 分结算。Java 附属可用 `.medal((context, scores, attributes) -> attributes.multiplyTotal("minecraft:generic.attack_damage", fraction))` 定义最终值百分比修饰，`fraction=0.01` 表示 +1%；原有 `attributes.add(...)` 仍是固定数值加算。属性只在容器饰品佩戴时由服务端应用；移除勋章或卸下饰品后会移除对应修饰。

内置 `deeprealm_4th:strength_gem`（力量晶石）每件提供 `+1` 力量，生效类型为 `STACKABLE`。战士勋章为 `UNIQUE_EFFECT`。

Java 附属可让物品继承 `AstralFillerItem`，构造时传入一个或多个完整翻译键；基类按顺序显示规则说明，并自动追加生效类型、有向冲突和“仅在装备中的星界躯体内结算”。动态数值可重写 `appendAstralTooltip`。本模组专属创造模式物品栏自动收录 `deeprealm_4th` 命名空间内的注册物品；其他模组命名空间的附属物品应加入附属自己的物品栏。当前正式物品各有独立的 16×16 透明贴图。

分数允许小数。分数转换可通过 `.conversion((context, currentScores, output) -> { ... })` 声明来源扣减和目标增加，扣减超过当前可用来源分数时整条规则按可用比例缩小。KubeJS 的 `AstralRules.convert(source, target, fraction, targetMultiplier)` 是便捷写法：扣除当前来源的指定比例，再将扣除量乘以倍率加到目标。

Java 也可使用 `ScoreRules.when(predicate, target, amount)`、`ScoreRules.perScore(source, target, multiplier)`、`ScoreRules.convert(source, target, fraction, targetMultiplier)`、`ScoreRules.attributePerScore(source, attributeId, multiplier)` 和 `ScoreRules.attributeMultiplyTotalPerScore(source, attributeId, fractionPerPoint)`。KubeJS 提供相应工厂及 `AstralRules.warriorMedal()`。`when` 的条件可读取 `FillerContext.player()`、`itemAt(x,y)` 和 `count(itemId)`；规则回调应保持只读。

## 继承容器物品

继承 `AstralContainerItem` 即可沿用物品栈存储、打开菜单、分数预览和 Curios 装备钩子。重写 `layout(ItemStack)` 提供不同尺寸；重写 `mayInsert(AstralInventory, int, ItemStack)` 时先调用 `super.mayInsert(...)`，再叠加限制。

```java
public final class SmallAstralBody extends AstralContainerItem {
    public SmallAstralBody(Properties properties) {
        super(properties);
    }

    @Override
    public ContainerLayout layout(ItemStack stack) {
        return ContainerLayout.parse(8, 6, List.of(
            "........", ".XXXXXX.", ".XXXXXX.",
            ".XXXXXX.", ".XXXXXX.", "........"));
    }
}
```

菜单根据布局尺寸和 `X`/`.` mask 生成格子。大于基础 12×9 的尺寸虽然在解析层允许，界面可能缩得难以操作，附属应在目标分辨率下检查可用性。物品栈不应堆叠；基类已将最大堆叠数设为 1。

附属容器要进入本模组专属的 Curios 槽，还须把物品加入 `curios:base_container` item tag。Forge 1.20.1 路径是 `data/curios/tags/items/base_container.json`，NeoForge 1.21.1 路径是 `data/curios/tags/item/base_container.json`：

```json
{"replace":false,"values":["addon:small_astral_body"]}
```

槽位守卫还会确认物品确实继承 `AstralContainerItem`，防止通用 Curios 标签让无关物品占用专属槽。

## KubeJS

安装与游戏版本匹配的 KubeJS 后，在 `kubejs/startup_scripts/` 中使用 `AstralFillers`、`FillerDefinition`、`ScoreType` 和 `AstralRules` 绑定。可运行示例见 [KubeJS 示例](../examples/astral-kubejs/README.md)，覆盖固定分、生命值条件、已有物品数量、相邻填充物、按分数加分、转换和勋章。修改启动脚本后重启游戏；同一物品 ID 在一次启动中只能注册一次。未安装 KubeJS 时，Java 内容仍可使用。

宝石承载星体力量、星座决定组合规则是项目设定。以上 `addon:*` 示例只验证 API，不构成正式的宝石、星体或星座对应关系。
